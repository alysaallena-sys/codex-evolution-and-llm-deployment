## Compact-Adviser: Separate Classification Advice from Task Recovery

The pinned source implements Compact-Adviser as an external classifier for context boundaries. The default path sends requests to `api.typesafe.ai/v1/systemone`. The default model name is `jev-latest`. Inputs can include user text, assistant text, tool-result excerpts, an older summary, artifact paths, and coverage markers. The payload contains more than token counts. The source caps the entire serialized request at 32,000 UTF-8 bytes. The historical review did not send or observe a real request. [Pinned source: judge.ts](https://github.com/kunchenguid/compact-adviser/blob/37fa1a665b8933de68c90014312060e862cf121a/packages/codex-plugin/src/judge.ts), [pinned source: snapshot.ts](https://github.com/kunchenguid/compact-adviser/blob/37fa1a665b8933de68c90014312060e862cf121a/packages/codex-plugin/src/snapshot.ts)

The Codex adapter in this version provides `hint` and `off` modes. The `hint` mode returns an advisory message. The adapter has no path that automatically performs compaction. Its default score uses `P(finished) × (0.5 + 0.5 × P(hands_on))`. Usage conditions can change the threshold from 0.90 to 0.50. The score expresses only a classification judgment. The `checkpointKey` uses a text hash only to deduplicate advice. It does not save recoverable task state. Recovery also requires separate storage and readback of the task goal, decisions, authorization boundaries, and next step. [Pinned source: config.ts](https://github.com/kunchenguid/compact-adviser/blob/37fa1a665b8933de68c90014312060e862cf121a/packages/codex-plugin/src/config.ts), [pinned source: hook.ts](https://github.com/kunchenguid/compact-adviser/blob/37fa1a665b8933de68c90014312060e862cf121a/packages/codex-plugin/src/hook.ts), [scoring source](https://github.com/kunchenguid/compact-adviser/blob/37fa1a665b8933de68c90014312060e862cf121a/packages/codex-plugin/src/judge.ts)

The shutdown order determines the actual boundary. In a valid `onStop` path, history reading, exchange completion, and session-state writing precede the `mode=off` check. The `off` mode then prevents key resolution, snapshot construction, and the classification request. The entry-point disable check runs earlier, before standard-input parsing and event handling. The historical review did not audit all import side effects. Therefore, neither `off` nor the entry-point check alone establishes zero reads and writes across the entire process. [Pinned source: hook.ts](https://github.com/kunchenguid/compact-adviser/blob/37fa1a665b8933de68c90014312060e862cf121a/packages/codex-plugin/src/hook.ts)

The history reader reads at most an 8 MiB tail. For long files, it also reads at most a 256 KiB header. The mapping limit is 4,096 messages. The selected assistant-message mapping does not check the channel. Secret patterns and sensitive-file heuristics provide only best-effort filtering. They do not establish that all personal information stays local. These conclusions describe potential static paths. The historical review did not establish an actual disclosure. [Pinned source: rollout.ts](https://github.com/kunchenguid/compact-adviser/blob/37fa1a665b8933de68c90014312060e862cf121a/packages/codex-plugin/src/rollout.ts), [filtering source](https://github.com/kunchenguid/compact-adviser/blob/37fa1a665b8933de68c90014312060e862cf121a/packages/codex-plugin/src/snapshot.ts)

The historical results support retention of the existing recovery method. They do not support installation or activation of this program. No local runtime evidence establishes classification accuracy, compaction safety, recovery quality, local token savings, or cost savings. The review also left the remote model's pricing and data-retention terms unverified.

## Browser Tools: Separate Execution, Caching, and Authorization

Deterministic action application in Playwright MCP does not establish that the model selected the correct target or workflow. The pinned README explicitly states that the tool does not constitute a security boundary. The extension can reuse a logged-in session. Login state provides operational capability only. The current task still requires separate authorization. The judgments about target selection and authorization here are adaptation conclusions. [Pinned README](https://github.com/microsoft/playwright-mcp/blob/50b004fb3d3ee17f9710f067ed1b6d59fd16e4a1/README.md)

The Stagehand documentation describes server-side result caching on Browserbase. Under the documented conditions, the cache option has no effect for a local browser. A `HIT` can eliminate LLM inference for that response. Neither `MISS` nor `DISABLED` establishes zero tokens, zero cost, or a fixed speedup for the entire task. [Pinned caching documentation](https://github.com/browserbase/stagehand/blob/ce298c60bd7e617e38d67db8db7d34de9d37cd18/packages/docs/v4/best-practices/caching.mdx)

The cache key includes the instruction, page content, options, and URL. It excludes model configuration. The `locator` or `ignoreLocators` option disables cache reads and writes for that call. An invalid selector or an unavailable cache can trigger fallback to inference. The two reviewed documents do not determine the final status value after selector fallback. This account records documented conditions only. The review did not run cache requests. [Pinned caching documentation](https://github.com/browserbase/stagehand/blob/ce298c60bd7e617e38d67db8db7d34de9d37cd18/packages/docs/v4/best-practices/caching.mdx)

Stagehand variables can hide actual values from the model. The cache service can still receive those values. The documentation requires `cache:false` for calls that contain credentials. It also requires logging to stop for secret inputs. The example code does not cover every requirement in the prose. Therefore, variable substitution or disabled caching alone does not establish complete confidentiality. The historical task did not change caching or logging configuration. [Pinned caching documentation](https://github.com/browserbase/stagehand/blob/ce298c60bd7e617e38d67db8db7d34de9d37cd18/packages/docs/v4/best-practices/caching.mdx), [pinned prompting documentation](https://github.com/browserbase/stagehand/blob/ce298c60bd7e617e38d67db8db7d34de9d37cd18/packages/docs/v4/best-practices/prompting-best-practices.mdx)

WebMCP requires the page to register tools. The pinned README distinguishes the imperative `registerTool` API from exploration of declarative forms. The specification marks its status as `CG-DRAFT`. The historical review did not find the older symbol `requestUserInteraction` in the fully retrieved pinned specification. Older examples and continuously updated browser guides therefore do not establish current API compatibility. [Pinned README](https://github.com/webmachinelearning/webmcp/blob/6cd745ac8a186122bd3f4aeaeb1d6cfa820251d2/README.md), [pinned specification](https://github.com/webmachinelearning/webmcp/blob/6cd745ac8a186122bd3f4aeaeb1d6cfa820251d2/index.bs)

Tool authors supply WebMCP annotations about read-only behavior, consequences, and untrusted content. The specification's non-normative security discussion notes that malicious pages can misrepresent those annotations. The agent still needs to check authorization. It also needs to read back actual effects. Annotations replace neither check. [Pinned specification: tool annotations and security discussion](https://github.com/webmachinelearning/webmcp/blob/6cd745ac8a186122bd3f4aeaeb1d6cfa820251d2/index.bs)

The historical receiving step only wrote six source conditions into task state and read them back. It retained the existing method and tool routing. A later receipt correction only added a `reason` field. The original validator then passed the structural check. This result did not establish practical effectiveness or program adoption. The historical task did not install or execute upstream software, call the cache, or run a paid model.

## ECC: Distinguish Entry Points and Costs by Host

The ECC v2.2.3 release README lists 68 agents, 293 skills, and 94 commands. The Codex plugin README in that same release still lists 281 skills. The source reviewer also reported counts of 71, 314, and 98 for the main-branch snapshot `b38be6a7f6350964d59328b52f0624e1d1d552d1`. The receiving reviewer did not reread that main-branch snapshot. These counts come from different documents or versions. They do not constitute an npm distribution-package inventory. [Pinned release README](https://github.com/affaan-m/ECC/blob/c05b2d6614f62f6db0047669aa4eefb223d478f9/README.md), [pinned Codex plugin README](https://github.com/affaan-m/ECC/blob/c05b2d6614f62f6db0047669aa4eefb223d478f9/.codex-plugin/README.md), [main-branch snapshot recorded by the source reviewer](https://github.com/affaan-m/ECC/tree/b38be6a7f6350964d59328b52f0624e1d1d552d1)

The quick-setup section in the release README targets the Claude plugin. The same README has a separate multi-host wizard and lists a Codex path. A local setup section therefore does not support the general claim that ECC lacks Codex support. The native Codex plugin, the deprecated legacy synchronization method, and opening ECC as a workspace are three distinct paths. Legacy synchronization writes to the host configuration directory. The documentation warns against combining legacy synchronization with the native plugin. [Pinned release README](https://github.com/affaan-m/ECC/blob/c05b2d6614f62f6db0047669aa4eefb223d478f9/README.md), [pinned Codex plugin README](https://github.com/affaan-m/ECC/blob/c05b2d6614f62f6db0047669aa4eefb223d478f9/.codex-plugin/README.md)

The Codex hook projection contains a Node command definition for `SessionStart`. That entry point can execute a program. Plugin registration, plugin activation, native-hook trust, MCP access, and task authorization are separate matters. The historical review only read hook definitions. It did not execute the commands. The startup chain, indirect dependencies, and complete data flow remain unaudited. [Pinned hook definitions](https://github.com/affaan-m/ECC/blob/c05b2d6614f62f6db0047669aa4eefb223d478f9/hooks/codex-hooks.json)

Component costs require at least the following four separate categories. Each needs measurements from the target host.

| Cost category | What to identify | Historical measurement |
| --- | --- | --- |
| Resident rules and entry points | Rules and entry points that the host actually loads | unknown |
| On-demand content | Skill and rule bodies that the current task actually reads | unknown |
| Catalogs and tool schemas | Metadata such as component catalogs and tool definitions | unknown |
| Subagents and runtime requests | Subagent calls, model requests, and service calls | unknown |

The cost documents contain behavior descriptions and estimates for Claude or specific tasks. They do not establish Codex's actual loading mechanism. `87 × 500 = 43,500 tokens` is only a documentation estimate. The historical task did not measure a fixed local overhead of 40k tokens. It also did not measure corresponding savings. Component counts and disk bytes cannot replace actual context-token measurements. Free code does not establish free models or services. [Pinned token documentation](https://github.com/affaan-m/ECC/blob/c05b2d6614f62f6db0047669aa4eefb223d478f9/docs/token-optimization.md), [pinned context-budget documentation](https://github.com/affaan-m/ECC/blob/c05b2d6614f62f6db0047669aa4eefb223d478f9/skills/context-budget/SKILL.md)

The historical ECC task only added an original cost-classification paragraph to an existing specialist guide and read it back. It retained the existing skills and runtime configuration. It did not install, synchronize, start, or activate hooks or enable MCP. Documentation integration establishes knowledge reuse. It does not establish ECC runtime acceptance.

## Rules for Using the Evidence

The source reviewer's reading of X does not establish that the receiving reviewer reread X. The receiving receipts for the browser sources and ECC explicitly retain this distinction. The Compact-Adviser receipt also states that the reviewer did not reread the original Chinese post. That handoff package recorded a complete automatic translation. The original export only compiled these receipts. It did not extend the coverage of the original reading.

Source claims, pinned documentation, static source code, local document readback, and runtime acceptance occupy different evidence levels. The historical results support version-bounded knowledge reuse. They do not establish current browser compatibility, account permissions, login state, actual bills, model performance, device behavior, or publication results.
